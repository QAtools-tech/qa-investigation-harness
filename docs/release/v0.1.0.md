# QA Investigation Harness 0.1.0 Release

**Registry status:** `0.1.0` is public under the default `latest` tag.<br>
**npm dist-tags verified 2026-11-13:** both `latest` and `preview` point to `0.1.0`.<br>
**Package:** `qa-investigation-harness@0.1.0`.

The first authenticated `npm publish --tag preview` completed as
`qa-investigation-harness@0.1.0`. npm briefly served a staging placeholder, then
made the operational release available under both tags. Attempts to remove
`latest` with npm CLI 11.13 and 12.2.2 both returned registry `E400`, so it
remains alongside the working `preview` tag.

## Included

- One project installer for Claude Code, Codex, and GitHub Copilot.
- The shared `qa-harness/` instructions, checks, fixtures, and adapters.
- Ten Agent Skills installed under `.claude/skills/`, `.agents/skills/`, or
  `.github/skills/` according to the selected client.

## Verification evidence

- The packed tarball was installed into separate clean consumers for all three
  clients. Each received ten skills, and the bundled artifact checker ran
  against its synthetic fixture.
- GitHub Actions `artifact-check` passed for [PR #26](https://github.com/QAtools-tech/qa-investigation-harness/pull/26).
- The local built-in Node suite passed: 119 tests, 0 failures.
- `npm pack --dry-run` listed 99 package files (119.2 kB).
- `npm publish --dry-run --tag preview` selected the `preview` tag and did not
  upload.
- Authenticated `npm publish --tag preview` completed after the npm security-key
  challenge. Its output reported 99 files and the expected tarball integrity.
  npm temporarily exposed a `0.0.0-stage` placeholder while the version was
  processed. The registry now lists `0.1.0` and both the `preview` and `latest`
  dist-tags point to it. The npm account's Staged Packages page is empty.
- Removing the unintended `latest` tag returned `E400` with npm CLI 11.13 and
  12.2.2 after account authorization; the registry tags remained unchanged.
- Public `npx --package qa-investigation-harness@preview` installs passed in
  separate empty projects for Claude Code, Codex, and Copilot. Each installed
  95 files and ten skills; the bundled checker reported two valid artifact
  files and zero diagnostics for every client.
- Claude Code ran the installed `qa-intake` skill against a synthetic case,
  produced the expected intake preview, and stopped for human confirmation
  before writing artifacts.
- VS Code Copilot resolved the installed `qa-intake` skill and reached an
  intake preview and confirmation question without writing artifacts. The
  Markdown case had an ambiguous list boundary that affected the expected
  result preview; rerun with clearer formatting before relying on that detail.
- Codex's installed skill files were present, but runtime execution stopped
  before the skill ran because the local OAuth refresh token was invalid and
  the selected model was unsupported for the tested account.

## Not verified

- Codex CLI workflow execution, due to the account/model setup blocker above.
- GitHub Copilot workflow execution in the full Visual Studio IDE; the runtime
  smoke used VS Code.
- Untagged public `npx` behavior; documented commands use `@latest` explicitly.
- Writing intake artifacts, browser exploration against a safe application,
  live Jira access, and downstream test-generation handoff.

## Install

Install the published release using `latest`:

```sh
npx --yes --package qa-investigation-harness@latest qa-investigation-harness install --client claude
npx --yes --package qa-investigation-harness@latest qa-investigation-harness install --client codex
npx --yes --package qa-investigation-harness@latest qa-investigation-harness install --client copilot
```

All three installs and bundled-fixture checks passed. The `preview` tag remains
as an alias for `0.1.0`; removing `latest` was rejected by the registry. The
`qa-investigation-harness@0.1.0` version is already published and cannot be
republished.
